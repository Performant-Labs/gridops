#172 Wireframe: GitLab Docker pool, default runner image (low-fi)

Scope: only the Docker image row (and the removal of any runner-group use) on four existing screens. Everything else on these screens is unchanged and omitted. Yellow notes are behaviour annotations. Marker * = required. All layout reuses SettingsSection / SettingsRow / Input.

1. New pool form: Runner definition, Docker image row

The row only exists while "Linux · Docker" is among the providers (unchanged). The state is driven by the platform descriptor for the current Targets selection (registry decides; no platform id in the route).

1a. No target yet / GitHub or Bitbucket target (today, unchanged)
Docker image
OCI image for each Linux runner.
ghcr.io/…/runner:latest
Required. Prefilled with options.defaults.dockerImage (GRIDOPS_RUNNER_IMAGE). Empty submit blocked by the browser (required) and by the schema with today's message.
1b. GitLab target selected, image never edited
Docker image optional
OCI image for each Linux runner. Leave empty to use gitlab/gitlab-runner:ubuntu-v19.6.0.
gitlab/gitlab-runner:ubuntu-v19.6.0
Not required, no asterisk. Field is empty (the GitHub default is NOT shown); the placeholder names the default. Help text is built from the descriptor's default-image text. Submit sends dockerImage: "" and no runnerGroupId.
1c. GitLab target selected, user typed an image
Docker image optional
OCI image for each Linux runner. Leave empty to use gitlab/gitlab-runner:ubuntu-v19.6.0.
registry.example.com/ci/gitlab-runner:1.2
Typed value is sent as is (server still validates a non-empty image). Switching Targets back to GitHub/Bitbucket keeps this typed value.
1d. Switch GitLab to GitHub (image left untouched by user)
Docker image
OCI image for each Linux runner.
ghcr.io/…/runner:latest
Back to 1a: required, GitHub default prefilled again. Rule: the field stores only what the user typed; the GitHub default is the fallback shown when the user has typed nothing and the platform has no default image. A typed value is never replaced in either direction.
1e. Error: server rejects a non-empty bad image (GitLab)
Docker image optional
bad image

Existing danger Callout "Could not create the pool". Empty is never an error for GitLab.
1f. Error: GitHub pool, image cleared
Docker image
Unchanged: browser required prompt; schema message "Docker image (dockerImage) is required for a pool that uses Linux · Docker." if it gets past the browser.
Not shown, intentionally: there is no runner-group control on any form today and none is added. GitLab pools simply stop sending a runnerGroupId (descriptor toCreatePayload no longer sends 1). Providers including Tart: Docker row is absent; Tart rules are unchanged.
