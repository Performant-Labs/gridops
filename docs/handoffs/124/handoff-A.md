## Summary
PASS, with no block and 8 warns. Both fixes extend the existing fixtures and add no parallel path:
- The Tart fix reuses the fake's existing `always-busy` branch instead of adding a new mechanism.
- The API fix puts the guard in a shared helper. The repo already has a place for that: `tests/support/*.rs`, pulled into each test binary with `#[path]` (`tests/support/openapi_schema.rs`).
- No production code is needed. The identity probe can use the existing `GET /api/v1/auth/me`.

The warns cover four gaps in the brief:
- `restart` cannot move to another port.
- Retrying must not seed the same database twice.
- One shared-helper file is compiled into two test binaries, so the helper's shape and the regression test's placement matter.
- The sweep misses one site of the same bind-and-release kind in gridops-manager.

They also cover a coexistence constraint with #134, and a secret-in-logs assertion that a per-fixture token would make vacuous.

- **A lead for `every_tart_command_gets_a_path_starting_with_tarts_directory` (`main.rs:3110-3155`)**, for T to confirm or rule out. A does not diagnose runtime causes.
  - The test waits on `calls_to("stop") < 2`. That reads `calls`, which the fake writes at the **start** of every command (`:2906`), before that command's `paths` line (`:2907`). The test then reads `paths` and parses every line (`:3128-3146`).

  - The crate already has the matching seam: `wait_for_stops(&tart, count)` (`:3532-3548`) waits on `stops-done`, which the fake writes at the **end** of `stop` (`:2945`).
  - If this is the cause, reuse `wait_for_stops(&tart, 2)` rather than a new wait.
  - If the cause is something else, such as `FakeTart::new`'s `fs::write`-plus-probe loop (`:3005-3021`), which differs from the `install_script` helper used for `ps` at `:3026`, say what in handoff-T, as the brief asks.
