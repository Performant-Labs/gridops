## Summary
BLOCK on one finding. The plan extends the right objects:
- the shared exit-reason table and its Tart copy;
- the reconciler's `Exit` and `left_service`;
- the two prep scripts, in place.

It builds no parallel path. But it adds 78 to a table whose entries both runner scripts reserve: each script moves `gitlab-runner run-single`'s own exit status out of the table when it collides with an entry. The brief extends neither guard. As written, a `run-single` that itself exits 78 would be listed as `runner_missing` on Tart. On Docker the result is worse: the manager reads container exit codes through core's table, so a Docker pool would get the "Tart image has no gitlab-runner" diagnosis.

There are seven warns. They cover where the script test runs, the helper shape, the stop-and-wait pattern, the `left_service` shape, the fleet path (already resolved), coexistence with #171/#172, and the naming and doc sweep.
