Comparison is after (HEAD, this branch) against before (the frontend built from the pre-branch commit 7164fda), both served by the same API binary and the same seeded data, headless Chromium via Playwright. The top 18 px strip (the build stamp, which reads "build unknown" in the before build because it has no git metadata) is blacked out in every image so it does not count as a difference. The wireframe is a low-fidelity sketch in another visual style and was used for content and copy, not pixels.

What I see different

  • Add connection, GitLab, Access token: the help paragraph is longer. It now names create_runner, manage_runner and read_api (or api) and asks for Maintainer or higher on a project, or Owner on a group. Before, it named two scopes and said the owner needs the Owner role on the project or group.
  • That paragraph is one line taller at all three widths (4 to 5 lines at 360, 2 to 3 lines at 768 and 1280), so the "Connect GitLab" and "Back" buttons sit about 20 px lower. Nothing is clipped, nothing overflows sideways, and the dialog still scrolls inside itself as before.
  • At 360 and 1280 the dialog is scrolled to the help paragraph (same step on both sides), so every field above it also appears shifted. That is the scroll position, not a change to those fields.
  • Runner pool overview with the seeded "GitLab runner not deleted" warning: no visible differences at any viewport. The amber warning dot, the event name, the truncated message, the "—" in the Runner column for a sweep row and the relative time all render the same before and after, because the table component is unchanged.
