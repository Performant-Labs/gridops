### WARN findings

**[W-1]** The open-jobs index's boundiness claim ("its cost is bounded by the number of open jobs, not by every job ever recorded") is weakened by the unresolved `Manual`/`Scheduled` question in B-7. If a project accumulates `Manual` jobs that never reach terminal status, the number of open jobs for that project grows without bound. Recommendation: either exclude `Manual`/`Scheduled` from the index predicate, or state in the #148 contract that it records terminal statuses for jobs it observes in the UI, or acknowledge that the index does not bound the scan for projects with many manual jobs.

**[W-2]** The `GitlabRunnerMaterial` token remains a `String`. The brief now adds a doc comment and a hand-written `Debug` that redacts it. The type is still a plain `String` in a public enum, so any code that serializes it with `derive(Debug)` on a containing struct would leak it. The `PrepareEnvironment` and `ExecutionConfiguration` structs are pinned unchanged, so this risk is bounded, but #139's sealed bootstrap material must carry this type and must not derive `Debug` on the enclosing type. Recommendation: add a note to #139 that the enclosing type's `Debug` must be hand-written or use a wrapper with redacting `Debug`.

**[W-3]** The `gitlab_runner_token` field in `ProvisionRunner` remains `Option<String>` in both crates. The brief specifies handling requirements (never logged, never in env/args), but the type itself is not a `SecretString`. Recommendation: #147 and #142 should use `SecretString` or a redacting newtype when they implement the actual launch, and audit existing logging.

**[W-4]** The `fleet_ci_targets` shape CHECK grows by three `IS NULL` terms per arm, as noted, but the brief pins the arms verbatim. The verbosity is acceptable for a migration that is specified to be rebuilt once.

**[W-5]** The OpenAPI `ApiErrorBody` shape is new, and #138/#141/#140 implement against it. The spec says errors "use a new `ApiErrorBody` component" rather than the Fleet `ErrorResponse`. This is a deliberate divergence. Recommendation: ensure #138's handler error mapping is consistent with this spec, since the live handlers may already return a different error body shape.

### NIT findings

**[NIT-1]** The `JobStatus` enum's `Unknown` variant is open in the index, which is fine, but the brief's "open" sentence in NIT-4 of the earlier rounds notes "Unknown jobs are open and stay in the open-jobs index." This is acceptable for a wave-0 contract.

**[NIT-2]** The `GitlabConnection` OpenAPI schema uses `scopeId` as integer, while `scope_id` in the schema is integer. The `scopeKind` is `"project"|"group"` as strings. This is consistent.

**[NIT-3]** The `wait_timeout_seconds` value is pinned at 600, and `GITLAB_DEFAULT_WAIT_TIMEOUT_SECS` is defined. The `GitlabRunnerMaterial` also has `wait_timeout_seconds: u32`. Whether these two constants must stay in sync is not stated; #139 owns the material, and #147 owns the script default. A test could assert that `GitlabRunnerMaterial.wait_timeout_seconds` defaults to `GITLAB_DEFAULT_WAIT_TIMEOUT_SECS` or that the two are explicitly decoupled. As written, both values are 600, but there is no acceptance criterion keeping them equal.
