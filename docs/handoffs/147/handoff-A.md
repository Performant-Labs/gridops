## Summary

BLOCK, with 1 block finding and 4 warnings. The amendments resolve all three round-1 blocks and all five round-1 warnings, and I checked each one against the code (see "Round-1 findings" below).

The new block comes from the B-2 amendment, which I asked for in round 1 without bounding it. B-2 makes a GitLab Start wait "a pinned timeout such as 60 s" for the readiness marker. Three facts in the code make that unsafe:

- The reconciler gives a start command 30 s (`START_COMMAND_DEADLINE_MILLIS`). Its doc comment says starts must take seconds.
- The agent runs one command at a time.
- The server's heartbeat path turns a delivered start that is past its deadline into an `uncertain` placement. It also cancels the commands queued behind that start and fails their placements.

So a slow or unreachable GitLab would harm other placements on the same host, not only the GitLab one. The fix is a one-line bound in the brief.

## Round-1 findings (all resolved)

- **B-1, the image. Resolved by D147-1, option (a).**
  - `docker.rs` keeps running `prepared.image` (`:238`), and the manager keeps running `input.image` (`main.rs:1818`). The manager's `validate` already requires a non-empty image for a non-native runner (`:404-407`), so the manager path always has a runner image.
  - The two new constants sit next to the other `GITLAB_*` constants in `provisioning.rs`, and they are additive.
  - `pool_docker_image` and `STOCK_DOCKER_IMAGE` (`fleet/targets.rs:449-473`) stay with #139.
- **B-2, which result reports the refusal. Resolved in shape** (the bound is the new finding 1).
  - Start reports `Configuration` with `RegistrationRefused`.
  - Every exited GitLab container inspects as `ResourceUnavailable`, so `placement::reported_gone` (`placement.rs:162-189`) still fires. Today's Inspect already reports any exited container that way (`docker.rs:312`), so GitLab only adds the diagnostic.
- **B-3, the diagnostic seam. Resolved.**
  - `dispatch::request` sends `prepared` with every placement-scoped call, Inspect included (`dispatch.rs:357-371`).
  - `CiTarget::is_gitlab()` exists (`domain.rs:204-207`).
  - The helper's socket call timeout is 330 s (`helper.rs:206`), so a longer Start fits on the helper side.
  - The list of constructors to update is incomplete; see W-1 below.
- **W-4 to W-8 (round 1). Resolved.**
  - `GitlabRunnerMaterial` is parsed directly, with no private copy.
  - A GitLab target without the socket is refused at Prepare, in `docker.rs::prepare`. That is the right layer: dispatch keeps its runtime-independent `Permission` checks (`dispatch.rs:244-246`), and the socket requirement belongs to the Docker executor.
  - The manager branches on platform, adds the `io.gridops.platform` label, reads `inspect_container` for the exit code, and refuses when there is no shared socket. Containers are created with `auto_remove: Some(false)` (`main.rs:1831`), so an exited GitLab container stays listable and `exitReason` can be read.
  - The docs name both socket settings.
  - The GitLab script is its own function. One part of how it takes its values is covered in W-2 below.
