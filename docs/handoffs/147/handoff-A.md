# Handoff-A: Phase 3 - GitLab: run gitlab-runner in Linux Docker runners (#147)  (up-front plan review)

**Date:** 2026-11-20
**Branch:** claude/gitlab-147-hostagent-e4a01d (head 621469b)
**Brief reviewed:** docs/handoffs/147-brief.md   **Reuse map:** N/A. No `survey.md` was provided. The baseline is the analogues the brief names: the GitHub JIT branch of `docker.rs`, the manager's `runner_command` and `provision_runner_inner`, the shared `instrumented_runner_script`, and the #137 contract (`b22c451`).   **Wireframe:** N/A (no UI surface)
**Verdict:** BLOCK

## Summary

BLOCK, with 3 block findings and 5 warnings.

Most of the plan fits the code:

- **One shared GitLab script in `gridops-core::provisioning`.** `instrumented_runner_script` is already the shared seam that both the host agent and the manager call.
- **Token delivery.** The token goes in on stdin, through `feed_secret` and the manager's attach, the same way GitHub's JIT config does.
- **Material parsing.** The host agent parses the core `GitlabRunnerMaterial`.
- **Advertising.** The D6 kinds go into `docker_backend`'s `supported_runners`.
- **Docker socket.** It reuses the existing socket grant.
- **Manager.** The `("gitlab", _)` placeholder is replaced, `exitReason` is read through `GITLAB_EXIT_REASONS`, and `ManagedRunner` gains `exit_reason` (D15).

The three blocks:

1. **The default runner image is placed in the host agent.** Today the server chooses the image and the agent runs whatever `PrepareEnvironment.image` names. "Overridable by the pool's `docker_image`" can't be implemented on either path.
2. **The brief doesn't say which command reports `RegistrationRefused`.** #137 pinned it to the start command's result, and the brief's restatement drops that. Today's Start can't observe a refusal. If the refusal is reported on Inspect as `Configuration`, the reconciler's `reported_gone` never fires, so the runner is never cleaned up.
3. **D5 needs a diagnostic channel that doesn't exist.** The helper protocol (`HelperResponse`) can't carry a diagnostic, and the brief's owned-file list doesn't include the files that would have to change.
