# Survey: forward-compat of the platform descriptor (#145 → #141 GitLab)

**Date:** 2026-11-20
**Branch:** claude/ui-145-platform-neutral-cf5832
**Contract:** `src/features/platform-connections/types.ts` (`PlatformDescriptor`, `TargetKind`, `ConnectionBindings`, `ConnectionField`, `PostCreateReveal`, `TargetOption`, `ManualEntry`)

#141 adds GitLab by writing `src/features/platform-connections/gitlab.tsx` (one `PlatformDescriptor`) and adding it to the `platforms` list in `registry.tsx`. Each need below is carried by a descriptor field, so the Connections page (`connections-section.tsx`), the Targets picker (`targets-row.tsx`) and the Platform options section (`platform-options-section.tsx`) need no change. Those three files hold no platform-specific code (`tests/platform-neutral-source.test.ts`), and `tests/targets-row-forward-compat.test.ts` shows a third, test-only descriptor appearing in the picker and the options section with no change to either.

## Statements required by the brief's Forward-compat note

1. **A GitLab pool still needs `schemas.ts` and API changes (#137).** The pool payload, `createRunnerPoolSchema` / `updateRunnerPoolSchema` in `src/features/runner-pools/schemas.ts` and the server contract know only `installationId`, `scope`, `repositoryIds`, `runnerGroupId` and `bitbucketConnectionIds` today. GitLab target fields (and making a non-GitHub kind standalone, since the create schema requires a positive `installationId`) need the schema and API changes of #137 before a GitLab descriptor's payload partial has anywhere to write.
2. **What lets #141 add GitLab without touching the page, picker or options components:** namespaced option keys (`TargetOption.key`), per-platform payload partials (`toCreatePayload` / `toUpdatePayload`), `requires` / `standalone` on each kind, per-kind limits (`limit`), the platform-options slot (`platformOptions.Component`), the post-create hook (`postCreate`) and the runner link builder (`runnerLink`), plus the declared list binding form (`connections.list.kind`), declarative connection fields (`connections.fields`) and the Add connection bindings (`connections.chooserDescription`, `connections.connectLink`).
