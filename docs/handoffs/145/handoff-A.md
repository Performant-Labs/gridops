## Summary
BLOCK, with one block finding. The three round-1 blocks are resolved:
- The reveal dialog now extends the extracted `SecretDialog`.
- A Reuse map exists, and the label rule stays in `schemas.ts`.
- The target-kind contract has namespaced keys, per-kind rules and per-platform payload partials.

The remaining block is the **Connections page loading seam**. The brief requires three things together: a route loader that settles every platform with `Promise.allSettled`, a page component that takes descriptors as a prop, and a Retry that re-runs only one platform. These cannot all hold, and they depart from the codebase's existing pattern for a list that can be retried on its own. Round 1's warn 8 recommended this loader design, so this finding corrects my own earlier advice.

## Notes for O
Amend `docs/handoffs/145-brief.md`, then start a fresh run.

1. **Block 1. Replace the "Connections page loading" paragraph (line 141) with this binding text:**
   - **Loading:** the connections list is loaded by `src/features/platform-connections/connections-section.tsx`. It receives `descriptors` (default `platforms`) and the `/settings` page data as props, and calls each descriptor's list binding itself. Each platform has its own load state. Use one existing pattern and name it in the brief:
     - `useQuery` keyed `["platform-connections", descriptor.id]` with `InlineError onRetry={refetch}`, as in `TokenListSection`, `api-tokens-section.tsx:228-246`; or
     - a `LoadState` with a per-platform attempt counter, as in `settings.ai.tsx:485-493`.
   - **Retry and refresh:** Retry re-runs only that platform's binding. After create, edit or remove, reload that platform through `useAction({ after })`. `router.invalidate()` (already called by `useAction` and `AsyncActionButton`) refreshes the `/settings` data.
   - **GitHub:** GitHub's list binding maps `page.data.installations` from props. It does no fetch, shows no loading state and has no Retry.
   - **Route:** `src/routes/settings.connections.tsx` has no loader and exports only `Route`. It reads `getRouteApi("/settings").useLoaderData()` and renders `SettingsLayout` with `ConnectionsSection` and `GitHubAppSection`, following the `settings.api-tokens.tsx` pattern.
   - **Tests:** the partial-load-failure, permission-gating and reveal tests render `ConnectionsSection` directly with injected descriptors and a stubbed `fetch`, as `tests/api-tokens-section.test.ts` does.
   - **Secrets:** the create call and the post-create hook's value never go through react-query.
   - **Cleanup:** delete "Route loader uses `Promise.allSettled` per platform" and "mutations call `router.invalidate()`" as the refresh mechanism. Wireframe B note 7's "while the loader runs" then reads as "while that platform's list loads".
