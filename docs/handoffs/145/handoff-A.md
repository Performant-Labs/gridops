# Handoff-A: Phase 4 - Platform-neutral UI, one Connections page and one Targets picker (#145)  (up-front plan review)

**Date:** 2026-11-20
**Branch:** claude/ui-145-platform-neutral-cf5832 (head 8526086)
**Brief reviewed:** docs/handoffs/145-brief.md   **Reuse map:** none exists (no `survey.md` under `docs/handoffs/145/` or `docs/handoffs/145-platform-neutral-ui/`); the brief's "Codebase starting points" and "Operating rules" were reviewed in its place   **Wireframe:** docs/handoffs/145/wireframe.html + docs/handoffs/145/handoff-D.md
**Verdict:** BLOCK

## Summary
BLOCK. The direction is sound and matches the codebase: a registry under `features/platform-connections`, a `settings.connections.tsx` route with redirect-only routes, an extended `SearchableMultiSelect`, and props-driven shared rows. Three gaps would build drift before T writes a test:
- The one-time reveal re-implements the existing, tested `SecretDialog` with conflicting dismissal rules.
- There is no Reuse map, so the label-rule validator would become a second source of truth next to `schemas.ts`.
- The target-kind contract is per-target and exclusion-only. The existing pool payload is an aggregate, with defaults owned by GitHub and a required GitHub target, so the contract cannot reproduce it.
