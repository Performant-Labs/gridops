## Summary

PASS. The plan extends the Tart agent's existing seams rather than building a parallel path:

- **Validation:** a `("gitlab", _)` arm in `ProvisionRunner::validate`.
- **Start:** a `"gitlab"` arm in `provision_runner`'s platform `match`, which hands the token to the shared `start_runner` stdin channel with `.take()` and `SecretString::from`.
- **Record:** `#[serde(default)]` additions to `TartRecord`, as `runtime` and `root` were added.
- **Listing:** a conditional key in `list_runners`.
- **Image script and docs:** a script modelled on the Bitbucket one, and a docs section placed next to Bitbucket's.

The new `gitlab.rs` sibling module is how the other binaries in this workspace split by concern: the manager has `vm_slots.rs` and `sandbox.rs`, the reconciler has `tart_lane.rs`. The plan keeps within this crate, as the epic's ownership table requires.

There are seven warnings and no blocks. Most concern how the waiter writes the exit code into the record store, and reusing the existing test fixtures rather than copying them.
