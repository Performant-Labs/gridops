# Handoff-A: Phase 3 - GitLab shared contract (#137)  (up-front plan review)

**Date:** 2026-11-20
**Branch:** claude/gitlab-137-contract-fa3bbe (head 4b0b494)
**Brief reviewed:** docs/handoffs/137-brief.md   **Reuse map:** N/A. No `survey.md` was provided, so the brief's own analogues (Bitbucket connection, client and runner columns; the GitHub fleet path) were used as the baseline.   **Wireframe:** N/A (no UI surface)
**Verdict:** BLOCK

## Summary

BLOCK, for three contract-shape problems. Each one would make the parallel wave-1 issues drift from one another or from the existing fleet architecture before a test exists.

1. `CiTarget` gains GitLab variants, but the only table that `PrepareEnvironment.target` is loaded from (`fleet_ci_targets`) can't store them. Migration 0046 doesn't touch that table, and no wave-1 issue owns it.
2. The brief carries the GitLab base URL in `ExecutionConfiguration`. The codebase's registration pattern is different: the URL travels in the sealed bootstrap material, next to the token (`github_registration { token, url, ... }`). As planned, the new field would also break older host agents for every platform.
3. `GitLabApi` doesn't say how a call is bound to a connection's base URL and access token, and `Scope` is undefined. The neighbouring `BitbucketClient` passes the token on every call and is held once in `AppState`. As listed, the trait can't serve more than one connection from the single `Arc<dyn GitLabApi>` that #138 plans to inject.

The rest of the plan fits the codebase:
- The module goes in `gridops-core` beside `bitbucket.rs` and `github.rs`, in the directory-module style that `fleet/` already uses.
- An `async_trait` seam has precedent in `gridops-agent` (`TurnModel`, `Sandbox`).
- A separate `gitlab_jobs` table is justified, because `workflow_jobs` is keyed by GitHub job id and tied to `workflow_runs` and GitHub repositories.
- `runner_pool_gitlab_connections` mirrors the Bitbucket table.
- The type names follow the existing split: `GitHubClient` for the client, `CiTarget::Github*` in the domain.
- The `runners` rebuild is a deliberate choice that the brief documents. 0020 avoided a rebuild only because an additive column was available, and none exists for widening a CHECK on the same column.
