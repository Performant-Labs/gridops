### WARN findings
- **[W-1]** scripts/fleet-health-guard.mjs:176-192 (`checkOwners`) — the brief's grep check says the guard's test "fails when an owned file (after glob expansion) is missing"; the implementation checks existence only for non-glob entries and explicitly allows globs matching nothing. This is a defensible reading (globs name files wave 1 will create), but it means a typo inside a glob path (e.g. `machine-*.tsx` vs a real prefix misspelling) is never caught — recommend documenting this reading in the design doc's Ownership section (it currently says "a glob that matches nothing yet is fine" only in code comments).
- **[W-2]** scripts/fleet-health-guard.mjs:117 (`checkFile`) — GitHub file statuses `changed`, `copied` and `unchanged` are not handled: a `copied` change from an owned path to a new path would be judged only on the destination, and an unrecognized status on a contract-test file falls through to the owns check instead of the stricter contract-test rule. Recommend treating any status other than `modified` on a contract-test file as a failure and any status other than `modified`/`added` on an owned file as needing explicit handling.

GET is safe so this is not a CSRF hole, but the design doc's session-route conventions are not shown to permit the asymmetry; confirm it matches how other settings GETs are written (`main.rs` settings routes not shown in full).
