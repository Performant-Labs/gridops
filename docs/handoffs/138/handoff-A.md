## Summary

BLOCK, with 1 block finding and 4 warn findings. Round 1's two block findings and its seven warnings are resolved. The test seam, the authorization rule, the layout, the wire names, the error status, the webhook URL, the PATCH plumbing, the delete rule and the secret storage are all now pinned, and each matches the code.

The new block comes from the amendment itself. The brief now gives GitLab pools a third `scope` value, `"gitlab"`, and says the required `installationId` "does not make a GitHub target". The code contradicts that. Everywhere it reads `scope`, it treats anything that isn't `"repository"` as a GitHub organization pool. In particular, the shared fleet-target function `fleet/targets.rs::pool_targets` derives a `github_organization` target from `installation_id`. The API's own fleet-settings save then writes it into `profile_ci_targets`, which admission reads. The brief tells #139 that these sites are "already inert", but it names only two of them, and no wave-1 issue owns `pool_targets`.
