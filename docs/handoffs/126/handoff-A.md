## Summary
BLOCK, with 2 block and 8 warn findings.
- **Block 1: the runner root must not go inside the work folder.**
  - The brief's preferred layout puts the per-environment runner root inside the work folder.
  - Runner 2.338.2 translates host paths to container paths by checking the work folder first. So `<work>/<root>/externals/node24/bin/node` reaches the job container as `/__w/<root>/externals/...`, not `/__e/...`.
  - In the job container that path is a symlink to a directory the container does not have. The root must live outside the work folder.
- **Block 2: the cache fill must not run in Start.**
  - The brief fills the per-image externals cache (about 600 MB) during Start.
  - A start command has 30 s, of which 25 s are usable, and the agent runs commands one at a time.
  - Heavy, cacheable staging belongs in Prepare. Prepare has a 20-minute deadline and already pulls the image, and `NativeRuntime` already stages there.
- **The rest of the plan is the right extension.**
  - Only the host agent changes: `docker.rs` and `work_folder.rs`.
  - The server needs no change. I checked this.
  - The existing cleanup is extended. No second cleanup path is added.
- **The warns settle the design choices the brief leaves to the architect,** so T and F build the same thing.
