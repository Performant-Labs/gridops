## Summary

BLOCK, with 1 block finding and 6 warnings. The amendments resolve all four round-1 blocks:

- **Round-1 block 1 (where the poll runs).** The poll is now its own worker beside `github_sync_worker`, with writes through `retry_when_busy`, a worker-local backoff map and a `poll_once` entry point. The reconcile interval can be read cheaply with `setting_i64`, the way `run_passes` reads it (`main.rs:405`).
- **Round-1 block 2 (id spaces).** A private key enum takes GitLab jobs out of the GitHub id spaces. GitLab jobs take room and are counted by `assigned_queued_jobs`, and every public output stays GitHub-only.
- **Round-1 block 3 (status tiers).** The status tiers are pinned, and `running` is not demand.
- **Round-1 block 4 (tag matching).** Tag matching is the pool's configured labels, which is what #139 registers.

The remaining block is in A-B1's bound on the conclusion step. It copies two of the three properties of the analogue's bound, `unconfirmed_jobs`, and leaves out the two that stop the check from being starved:

- **A re-check interval.** The analogue records `checked_at` before each request.
- **Priority for waiting rows.** The analogue checks waiting jobs before running ones.

As written, `running` rows whose status hasn't changed take the check's slots on every poll. A stale `pending` row (the only kind the scaler counts) then stays as false demand until enough older rows conclude. Round 1's suggested fix named only `status_changed_at` as the age, so that wording was incomplete. The analogue measures age from the last report *or* check.
