**Placement decisions, with no drift found (recorded for T and F):**
- **The cutoffs, settings reads, per-table loop and logging stay in the reconciler.** `cleanup_retention` builds `(RetentionTable, cutoff)` for each table from `setting_i64`. It calls `retention::prune` and matches on the result, exactly as the existing `prune_inventory_snapshots` wrapper does (`main.rs:3363-3385`):
  - `Ok(0)` → nothing;
  - `Ok(n)` → `info!(table = table.as_str(), deleted = n, …)`;
  - `Err` → `warn!(table = table.as_str(), error = ?error, …)`, then continue.
  - Core returns `Result<u64, sqlx::Error>` and doesn't log; core has two `tracing::` calls in total.
  - Computing the cutoff per table through an exhaustive `match` over `RetentionTable::ALL` would make a new variant without a cutoff fail to compile. I recommend it but don't require it.
- **Error isolation is therefore reconciler wiring, so its test is a reconciler test.** The precedent is `a_failing_snapshot_prune_does_not_stop_the_rest_of_the_cleanup` in `crates/gridops-reconciler/src/snapshot_retention_tests.rs`.
  - Extend that file and reuse its `Harness`. Each reconciler test file builds its own `Reconciler`, and there's no shared harness.
  - Inject the failure with its `BEFORE DELETE … RAISE(ABORT)` trigger rather than dropping a table. A trigger fails only the delete, and each test gets its own database (brief-review W-2).
- **Rename the reconciler's local alias.** `main.rs:3364` has the fn-local `use gridops_core::fleet::registry::snapshot_retention as retention;`, which would shadow a `gridops_core::retention` import. Rename the alias (for example to `snapshots`) so that `retention::` means one thing in the file.

**Checked and consistent (no finding):**
- **NV-3 is resolved.** The api runs `MIGRATOR` inside `connect_database` before it serves (`gridops-api/src/main.rs:87`, `db.rs:44-48`). In `compose.yaml`, `reconciler` `depends_on` `api: service_healthy`, so the index build can't race the reconciler.
- **W-3 is resolved.** sqlx-sqlite 0.9 applies each migration and its `_sqlx_migrations` row in one transaction (`migrate.rs:165-176`), so 0050 can't half-apply. Leaving out `IF NOT EXISTS` matches 0034 and 0049.
- **NV-4 is confirmed.** The indexes are `audit_events_created_idx` (0001:14), `webhook_deliveries_received_idx` and `capacity_samples_recorded_idx` (0034), and `reconciler_passes_started_idx`. That last one is in 0036:9, not 0001 as the brief says, which changes nothing.
- **All five tables are rowid tables.** No migration declares `WITHOUT ROWID`, so the `rowid IN (…)` shape is valid for each.
- **NV-5 is confirmed.** `snapshot_retention.rs` has `BATCH_SIZE = 500`, `MAX_BATCHES = 40` and `BATCH_PAUSE = 25 ms`. Each batch is a bare `.execute(pool)`, with no transaction across batches.
- **The bundled SQLite is libsqlite3-sys 0.37.0 (3.51.3).** #152's review found its plan text matches the 3.54 CLI for this statement shape. Asserting `ends_with("INDEX <idx> (<col><?)")` still holds if the bundled library ever omits "COVERING".
